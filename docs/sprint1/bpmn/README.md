# Моделі бізнес-процесів (BPMN 2.0)

Каталог містить схеми бізнес-процесів онлайн-банкінгу «ФінКит» для Спринту 1, розроблені відповідно до специфікації `product.md` та канонічного порядку розділу 4.3 Каталогу продуктів.

## Інструмент моделювання

- Редактор: draw.io (diagrams.net), версія формату файлів 21.0.0 (див. атрибут `version` у заголовку `.drawio`)
- Формат файлів: `.drawio` (XML)
- Способи відкриття та редагування:
  - Онлайн: сервіс https://app.diagrams.net/ (меню File -> Open from -> Device)
  - VS Code: розширення «Draw.io Integration»
  - Десктоп: додаток draw.io Desktop

## Склад моделей

Нумерація моделей відповідає канонічному порядку розділу 4.3 Каталогу продуктів (за протоколом рецензування Скрам-майстра):

### 1. Відкриття рахунку (`01_account.drawio`)
- Специфікація: `product.md`, розділ 3.1 (Каталог 4.3)
- Пули: Клієнт, Банк (Система, Операціоніст)
- Ключова логіка: KYC-верифікація нових клієнтів операціоністом (шлюз «12. Документи коректні?»), єдиний шлюз злиття 14 (зайвий шлюз 15 вилучено за дефектом А-02), валідація суми первинного внеску від 100 грн.

### 2. Переказ коштів (`02_transfer.drawio`)
- Специфікація: `product.md`, розділ 3.2 (Каталог 4.3)
- Пули: Клієнт, Банк (Система, Операціоніст), Процесинговий центр
- Ключова логіка: паралельний шлюз (AND) для атомарного дебетування та кредитування, перевірка добового ліміту 50 000 грн з ескалацією на операціоніста (шлюз «17. Операцію підтверджено?»), початкова подія-повідомлення в пулі Процесингу.

### 3. Оформлення кредиту (`03_loan.drawio`)
- Специфікація: `product.md`, розділ 3.3 (Каталог 4.3)
- Пули: Клієнт, Банк (Система, Ризик-менеджер, Операціоніст)
- Ключова логіка: обов'язковий автоскоринг для всіх заявок (шлюз 15 передає заявки >400 000 грн до ризик-менеджера разом із результатом скорингу за дефектом А-01), ручний розгляд ризик-менеджером (шлюз «17. Заявку погоджено?»), ловляча подія «Пропозицію отримано» після шлюзу подій 4, очікування підписання договору 7 днів за таймером.

### 4. Оплата рахунку (`04_payment.drawio`)
- Специфікація: `product.md`, розділ 3.4 (Каталог 4.3)
- Пули: Клієнт, Банк (Система), Одержувач платежу
- Ключова логіка: автоматичний розрахунок комісії банку, валідація реквізитів одержувача (шлюз «11. Реквізити вірні?»), прямий зв'язок повідомлень, формування платіжного доручення одержувачу.

## Правила нотації BPMN 2.0

- Sequence Flow (суцільна стрілка) — виключно внутрішні переходи в межах одного пулу.
- Message Flow (пунктирна стрілка з колом на початку) — взаємодія між різними пулами.
- Gateways — усі шлюзи мають явні графічні маркери нотації (+, ×, event-based) та змістовні умови на гілках.
- Data Objects / Stores — відображають документообіг (реквізити, квитанції, доручення) та сховище рахунків.
- Text Annotations — обов'язково зв'язані пунктирною лінією асоціації з відповідним вузлом.
