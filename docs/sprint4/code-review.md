Умовні позначення пунктів чек-листа 5.3 (1..8):
1. `@DisplayName` містить ID `BL-xx` або `TC-xxx`; очікуване значення взято зі специфікації, а не з поведінки коду.
2. Читається структура AAA; один тест - одна причина впасти.
3. Ім'я методу описує поведінку, а не порядковий номер.
4. Граничні значення перевірено з обох боків межі; діапазони оформлено через `@ParameterizedTest`.
5. Винятки перевірено через `assertThrows` із конкретним типом; `BigDecimal` перевірено з урахуванням шкали.
6. Тест незалежний від порядку і стану; UI-тест сам відкриває і закриває браузер.
7. У UI-тесті відсутні `Thread.sleep`, `implicitlyWait` і абсолютні XPath; використано `WebDriverWait` та стійкі локатори.
8. Падаючий тест має посилання на зареєстрований `BUG-xxx` у коментарі; підігнаних очікувань і невмотивованих `@Disabled` немає.

## 4. Перевірка звітів про дефекти модуля `finkit/v1` (чек-лист 13.2)

Правила чек-листа 13.2 (1..7):
1. Дефект повністю описано словами; вкладення ілюструє текст.
2. Один звіт - один дефект.
3. Містить усе для відтворення (середовище, кроки з даними, фактичний і очікуваний результат).
4. Кроки написані послідовно без пропусків.
5. Звіт зрозумілий з першого прочитання; Title відображає суть без читання опису.
6. Текст грамотний, посилається на точні номери рядків / стектрейси та вимоги з ID.
